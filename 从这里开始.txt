仍为 "1.0"（与插件版本 v2.1.0 是两回事）。

（Sample/DESIGN）实跑一轮，总判定 **failed（未整体通过）**，逐条证据见 验收\real_test_result.json：

⇒ 转换引擎与安装/卸载可用；「PDMS 里一键建树/导出」端到端在本机环境尚未走通。

1. 先读什么：插件包\docs\使用说明.md（三种用法谁是主、装在哪一步、已知限制）。
   本次改了什么 / 与 v2.0 差异 / 旧版迁移：docs\README_v2.1.0.md。
   原生 .NET 插件另见：PDMS原生插件\README.txt 与 插件包\docs\原生插件说明.md。

2. 主用法：在 PDMS 里用——菜单「PKPM2PDMS」→「PKPM2PDMS导入导出」打开原生窗体：
   选文件、点执行、看摘要；转换 / 建 PDMS 模型 / 截面库 / 导出都在这个窗体里。

3. 装在哪一步（务必 PDMS 停机时；2026-09-28 实机测试已走通一轮安装→测试→卸载并把
   PDMS 配置逐字节复原，你的正式安装仍按下面步骤自己执行）：
   ① 主路线（原生 .NET 插件）：cd PDMS原生插件\deploy 后  python deploy_pkpm2pdms.py  先 dry-run
      看清单，再  python deploy_pkpm2pdms.py --execute  真执行；装完启动 PDMS 出「PKPM2PDMS」菜单。
   ② legacy（PML 菜单，标题「PKPM2PDMS PML」）：插件包\install\install.ps1 先 -DryRun 再真装——
      原生窗体的「PDMS 文本导出」按钮依赖它装的 !!pkpm2pdmsexport；不用导出功能可跳过。
      （两条路线是**两个**菜单，名字不同，便于分辨哪条生效。）
   ③ 两条路线装完都要【完全退出并重启 PDMS】。

4. 免 Python 的转换入口（本次构建产物）：
   安装程序\PKPM2PDMS_引擎_v2.1.0.exe        —— 转换引擎（tkinter 界面 + --cli 命令行）
   插件包\engine\dist\pkpm2pdms_engine.exe   —— 同一份引擎的副本，供 .NET 窗体的 engine_path 使用
   安装程序\PKPM2PDMS_安装程序_v2.1.0.exe      —— 图形安装程序（安装/卸载向导）
   插件包\pdms-net\dist\PKPM2PDMS.dll        —— 原生插件程序集（AssemblyVersion 2.1.0.0）
   以上 exe/DLL 均由本次构建产出（2026-09-28 缺陷修复后重建），SHA256 见 交付清单.txt 第三节。

5. 卸载（同样 PDMS 停机时）：原生插件  python undeploy_pkpm2pdms.py （先 dry-run；XML 从
   .pkpm2pdms-bak 逐字节复原、安装文件移入 _uninstalled_<时间>\，不删除）；
   legacy：插件包\install\uninstall.ps1（先 -DryRun）。
   ⚠ v2.0 时代装在机器上的旧名安装（PKPMJWD.dll / PMLLIB\pkpmjwd\ / .pkpmjwd-bak）
   新版**识别不到**：请先用 v2.0 的卸载脚本卸干净，再装 v2.1.0。

6. 版本号的三层含义（别混）：
   插件版本            v2.1.0 / 2.1.0.0   —— exe 文件名、DLL AssemblyVersion、GUI 标题、本清单
   规范模型 schema 版本  CONTRACT_VERSION = "1.0"（engine/canonical.py）—— 不变
   格式版本            PDMSDUMP 1.0 / .pdt $VERSION 4.2.0 / UIC <Version>1.0 —— 不变

逐文件清单与 SHA256 见同目录 交付清单.txt 与 SHA256哈希清单.txt。
