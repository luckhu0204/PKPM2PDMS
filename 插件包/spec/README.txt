spec/ —— 接口契约（本包唯一的技术裁决处）
========================================

文件
----
  CONTRACT.md   **唯一接口契约 v1.0**。内容覆盖：
                  §a 规范模型 API（canonical.py 的数据类 / JSON / validate）
                  §b 各模块函数签名（5 个实施包之间只允许通过这些交互）
                  §c PDMSDUMP 1.0 文本格式（文法 + 最小示例 + GBK/CRLF/缺省单位）
                  §d PDMS 实体层级与命名 + 允许使用的 PDMS 语法（逐条带本机出处）
                  §e 截面解析优先级（四级）+ 匹配文件容错 + 补充文件规则
                  §f 命令行与图形界面签名 + 退出码
                  §g 编码与产物纪律
                  §h 报告策略（report.json 结构）
                  §i 范围边界（明令不做）
                  §12 仍存歧义/未证实清单（含本契约的裁定与"待实机确认"标记）
                  附录 A/B/C 最小示例、证据行号表、本次实测命令与输出
  out/          导出/留档的样例与固件（见 out/README.txt）

使用规则
--------
  1. 实施前先读 CONTRACT.md 的相关章节；签名、字段名、状态字符串、行标记、PDMS 命名以它为准。
  2. 发现契约有误或有缺：**先改 CONTRACT.md**（唯一入口），再改代码；不要私自在代码里扩展。
  3. 任何 PDMS 语法都必须带"本机安装内文件:行号"的出处；没有出处的写法禁止使用。
  4. 契约的每条结论都带证据分级（【事实】/【推断】/【未知】）；实施时不得把【推断】升级成事实。
  5. 契约里标注"待实机确认"的项，只有在 PDMS 实机跑过并留证据后才能改成结论。

本目录由架构包维护；其他实施包只能**追加**新文件（如 CONTRACT-AMEND-*.md），
不得直接改写既有条文——改写必须走 §0.3 的变更规则并在文件头记录变更日期与理由。
