## 1. 这是什么

把 .NET WinForms 窗体挂进 **PDMS 原生菜单/工具条**（像现有《PKPM导入导出插件》那样：
菜单点开一个窗体）。三层分工（契约 §p.4，**混写红线**：谁也不越界）：

| 层 | 职责 | 机制 |
|---|---|---|
| **.NET**（`dist\PKPM2PDMS.dll`，40,960 B） | 菜单/窗体呈现、参数收集、进度与摘要、日志、弹窗 | `IAddin` + `Command`（Aveva.ApplicationFramework） |
| **PML** | **PDMS 库内**一切动作：遍历模型写 PDMSDUMP、导入宏执行（`$M`）、**重名唯一化**（`!!pkpm2pdmsUniquename`，见 `docs/重名处理说明.md`） | `Command.CreateCommand(s).Run()/Result`（.NET→PML） |
| **Python 引擎**（R3 起有独立可执行入口） | 全部文件格式转换（12 个子命令，与命令行**同一套执行函数**） | .NET 以**进程方式**调用：`<engine> --request <JSON>`（契约 §p.5） |

源码 5 个文件（`pdms-net\`）：`PKPM2PDMSAddin.cs`（IAddin 入口）、`PKPM2PDMSForm.cs`（窗体）、
`PmlBridge.cs`（.NET↔PML 桥，3 个冻结方法）、`EngineRunner.cs`（引擎进程调用）、`PKLog.cs`
（日志 `<PDMS根>\PKPM2PDMS\addin.log`）。骨架照抄参考插件 TGTEXT（本机备份副本
`D:\AI_Work\pmds三维文字程序-备份\TGTEXT\`，逐行出处见契约附录 F.4）。

## 2. 怎么编译（`build.cmd` 原样命令；已真跑通过）

前置：本机已有 `C:\Windows\Microsoft.NET\Framework\v3.5\csc.exe`（.NET 3.5 / CLR 2.0）与
`D:\AVEVA\Plant\PDMS12.1.SP4` 下的 Aveva 程序集（**只读引用**）。不需要 VS / dotnet SDK / 强名称 / GAC。

```bat
cd /d D:\AI_Work\PKPM数据解析\PKPM2PDMS导入导出\pdms-net
build.cmd
```

`build.cmd` 的编译命令逐字（`build.cmd:23-33`；`build.cmd:7-21` 是 csc 定位与**源码定位器**——
支持脚本在 `pdms-net\` 内、被暂存到上级、或被暂存到含 `PKPM2PDMS*\` 的目录三种布局）：

```bat
"%CSC%" /nologo /target:library /platform:x86 /optimize+ /utf8output /codepage:65001 ^
 /warnaserror- /out:"%SRC%dist\PKPM2PDMS.dll" ^
 /r:"%PDMS%\Aveva.ApplicationFramework.dll" ^
 /r:"%PDMS%\Aveva.ApplicationFramework.Presentation.dll" ^
 /r:"%PDMS%\Aveva.Pdms.Database.dll" ^
 /r:"%PDMS%\Aveva.Pdms.Utilities.dll" ^
 /r:"%PDMS%\Aveva.Pdms.Geometry.dll" ^
 /r:System.dll /r:System.Core.dll /r:System.Drawing.dll ^
 /r:System.Windows.Forms.dll ^
 "%SRC%PKPM2PDMSAddin.cs" "%SRC%PKPM2PDMSForm.cs" "%SRC%PmlBridge.cs" ^
 "%SRC%EngineRunner.cs" "%SRC%PKLog.cs"
```

**实测**（验收检查 16 + 独立复核）：退出码 0，`BUILD OK`；产物 `dist\PKPM2PDMS.dll` 40,960 字节；
PE 头独立解析 `Machine=0x014C(I386)、OptMagic=0x010B(PE32)、RuntimeVer=2.5、元数据串 ASCII
"v2.0.50727"、CorFlags=0x3（ILOnly+32BITREQUIRED）`；旁证 TGTEXT.dll 同为 CLR 2.0/x86。
**必须用 csc 3.5 + `/platform:x86`**：PDMS 的 des.exe 是 CLR v2.0.50727、Aveva.Pdms.* 标
Requires32Bit。`D:\AVEVA` 在编译前后零变化（编译只读）。

编译期踩过的两个坑（源码注释留证）：Timer 二义性全限定；`Command.Error` 的静态类型是
`PdmsMessage` 而非 string（csc 报 CS0173 实测得出）⇒ `PmlBridge.SafeError` 用 object+ToString。

## 3. 怎么安装（**必须 PDMS 停机时**；缺省 dry-run，先看清单再执行）

安装 = **纯文件注册**（不改注册表、不进 GAC），共 5 步（契约 §p.6）：

| 步 | 改什么 |
|---|---|
| ① | 备份 `<PDMS根>\DesignAddins.xml`、`<PDMS根>\DesignCustomization.xml` 各一次（后缀 `.pkpm2pdms-bak`，只备一次） |
| ② | `DesignAddins.xml` 的 `</ArrayOfString>` 前插 `  <string>PKPM2PDMS</string>`（幂等：已有则跳过） |
| ③ | `DesignCustomization.xml` 的 `</UICustomizationFiles>` 前插 `  <CustomizationFile Name="PKPM2PDMS" Path="pkpm2pdms.uic" />` ← **最容易漏的一步** |
| ④ | 复制 `dist\PKPM2PDMS.dll`、`dist\pkpm2pdms.uic` 到 `<PDMS根>\` |
| ⑤ | 写 `<PDMS根>\PKPM2PDMS\engine_path.txt`（引擎入口绝对路径）；复制 `pdms\pkpm2pdmsuniquename.pmlfnc` 到 `<PDMS根>\PKPM2PDMS\pml\`（GBK+CRLF 原样字节复制） |

```bat
cd /d D:\AI_Work\PKPM数据解析\PKPM2PDMS导入导出\pdms-net\deploy
python deploy_pkpm2pdms.py                 :: 先 dry-run：打印"将要改变的全部对象"完整清单（8 项），不落盘
python deploy_pkpm2pdms.py --execute       :: 确认清单无误后再真执行（PDMS 停机！）
:: 然后启动 PDMS → DESIGN 模块 → 菜单栏出现「PKPM2PDMS」
```

选项：`--engine-entry <PATH>` 显式指定引擎入口（写进 engine_path.txt；缺省自动找
`engine\dist\pkpm2pdms_engine.exe`，回退 `run_engine.cmd`）；`--pdms-root <DIR>` 只用于测试。

**实测**（验收检查 17 + 独立复核用自己的 %TEMP% 沙箱）：dry-run 打印 8 项清单（backup×2 +
insert×2 + copy×3 + write×1，**无删除字样**）且零写入；`--execute` 后两个 XML 各恰 1 处
`PKPM2PDMS` 条目、BOM 保留（两 XML 均 UTF-8 带 BOM + CRLF）、CRLF 恰各加 1 行、`.pkpm2pdms-bak`
生成；**连跑两次幂等**（第二次后 XML 逐字节不变）；失败回滚与写后校验在脚本内。

> 引擎本体**不复制**进 PDMS 目录（`engine_path.txt` 指回工作区/交付目录）；
> PDMS 安装目录以外不落任何文件。

## 4. 怎么卸载（同样 PDMS 停机时；恢复优先，无删除）

```bat
cd /d D:\AI_Work\PKPM数据解析\PKPM2PDMS导入导出\pdms-net\deploy
python undeploy_pkpm2pdms.py               :: 先 dry-run
python undeploy_pkpm2pdms.py --execute
```

行为（实测）：① 两个 XML 从 `.pkpm2pdms-bak` **逐字节复原**；② 安装过的 4 个文件
（`PKPM2PDMS.dll` / `pkpm2pdms.uic` / `engine_path.txt` / `pkpm2pdmsuniquename.pmlfnc`）
**移动**到 `<PDMS根>\PKPM2PDMS\_uninstalled_<时间戳>\`（不删除）；③ `.pkpm2pdms-bak` 保留。
实测输出 `restore 2 + move 4`，XML 与备份逐字节相等（Base64 比对）。

## 5. 菜单在哪、窗体长什么样

**菜单**（`pkpm2pdms.uic`，与参考件 `tgtext.uic` **逐条同构**——验收检查 18 的同构对照表逐项 True，
仅 Name/Caption/Key 不同；UTF-8 无 BOM + LF，与在用的 tgtext.uic 字节形态一致）：

* 菜单栏 **「PKPM2PDMS」**（MenuTool `PKPM2PDMS.Menu`）→ 按钮 **「PKPM2PDMS导入导出」**
  （ButtonTool `PKPM2PDMS.Open`，Command `<Type>Instance</Type><Key>PKPM2PDMS.OpenTools</Key>`）；
* 同时挂快速访问条（QATTools）；
* Key **三处一致**（实测）：`.uic` 的 `<Key>` = `PKPM2PDMSAddin.cs` 的 `Command.Key` = Command 构造器；
  `IAddin.Name` 返回 `"PKPM2PDMS"`（= DesignAddins.xml 的条目文本）。

**窗体 `PKPM2PDMSForm`**（WinForms，非模态、Owner=PDMS 主窗，标题「PKPM2PDMS导入导出」；
控件清单冻结于契约 §p.3，验收检查 18 实测 26 个控件名缺无）。自上而下：

| 区 | 控件 | 说明 |
|---|---|---|
| 操作 | `cmbOp`（下拉） | 10 个操作：`jwd2pdms / pdt2pdms / pdms2jwd / pdms2pdt / jwd2db / pdt2db / db2jwd / db2pdt / jwd2pdt / pdt2jwd`；缺省 `jwd2pdms` |
| 输入 | `txtSource`+浏览 | 源文件（`.jwd`/`.pdt`/目录宏 `.txt`/PDMSDUMP `.txt`），类型按扩展名判定，**不设格式下拉** |
| | `txtSecmap`+浏览 | 截面匹配文件；缺省 = 源文件同目录 `PKPM转PDMS截面匹配文件.txt` |
| | `chkUseExtra` | 补充映射（缺省勾选 = 自动加载 `engine\secmap_extra.txt`） |
| 建模参数 | `numBaseE/N/U`、`numAngle`、`cmbUnit` | 基点/转角/单位（仅 `*2pdms` 方向启用；单位只缩放宏内数值） |
| 构件类别 | 8 个 CheckBox（`chkColumn…chkHole`） | 按契约 §p.3-8 保留；**暂未传给引擎**（CLI 无对应参数，复核条目注明） |
| 输出 | `txtOut`+浏览 | 缺省 `%TEMP%\PKPM2PDMS\<源基名>.<ext>` |
| 执行 | `btnRun` + `progressBar1` | 同步等引擎退出（超时上限 30 分钟）；建模方向成功后自动 `RunPml("$M <宏>")` 并取回改名记录 |
| 结果 | `txtSummary`、`btnOpenReport` | 摘要（计数+未解析清单+改名数）与打开 report.json |

## 6. 与 PML / 引擎的分工、与旧方案的边界

* **引擎调用协议**（契约 §p.5）：`<engine_entry> --request <UTF-8 JSON>`，
  `{"tool":"jwd2pdms","args":{…}}`（键名 = CLI 长选项去 `--`）。入口解析顺序：
  ① 环境变量 `PKPM2PDMS_ENGINE` → ② `<PDMS根>\PKPM2PDMS\engine_path.txt` →
  ③ `<DLL 目录>\..\..\engine\dist\pkpm2pdms_engine.exe`。引擎侧已实现（`engine/cli.py:2227-2358`
  的 `--request` 分支），复核确认与 `EngineRunner.cs` 的键名/位置参数/base 三元组/store_true
  逐项对齐。构建方式：首选 PyInstaller `--onefile`（产物 `engine\dist\pkpm2pdms_engine.exe`
  8,866,520 B 已在包内），回退 `engine\dist\run_engine.cmd`（定位本机 Python 后调 `cli.py`）。
* **导出方向的 PML 依赖（重要，复核发现的 medium）**：窗体「导出当前模型」调
  `!!pkpm2pdmsexport(!!CE,'<path>')`，该函数**不由 deploy 安装**，而是随 **v1 的
  `install\install.ps1`** 复制到 `<PDMS根>\PMLLIB\pkpm2pdms\` 并由 `pkpm2pdmsrun.mac` `$M` 载入
  ⇒ 要用窗体的导出功能，需先按 `docs/使用说明.md` §2 装 PML 包（legacy 路线），
  或在 PDMS 命令行手动 `$M <包>\pdms\pkpm2pdmsexport.pmlfnc`；否则该按钮报"找不到 PML 函数"
  （失败路径干净：MessageBox+日志，不会半截写文件）。
* **旧方案的关系**（契约 §p.8）：`install\install.ps1`（PML 菜单注入）已被 §p 取代为 **legacy**
  （文件保留）；交付目录 `安装程序\` 里的两个 v1 exe 是更早的遗留方案（只装 PML 菜单，
  不含 .NET 插件）；`engine\gui.py`（tkinter）保留为开发/测试工具。对用户**只暴露 PDMS 内窗体**。
