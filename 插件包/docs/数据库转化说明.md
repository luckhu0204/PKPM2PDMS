## 1. 什么是"数据库层面的转化"

"数据库"指 PDMS 的 **Catalogue（目录）+ Specification（等级/规格）**——即截面库本身，
不是 Design 模型里的构件。两侧的截面定义通过一张**转化表**（`engine/section_table.csv`，
见 `docs/转化表说明.md`）双向互算：

```
                ┌── .jwd   pkpm{Col,Beam,Brace}Sect（Kind / ShapeVal 编码）
PKPM 截面定义 ──┤
                └── .pdt   $DEFFRAMESECTION / $DEFWASLABSECTION / $DEFMATERIAL
      ⇅（族码表 + 尺寸参数双向互算；信息损失逐项申报，见 §7）
PDMS 数据库 ────  Catalogue：STSECTION / STCATEGORY / TEXT / DTSET / PTSSET / GMSSET / SPRFILE
                  Specification：SPWLD / SPECIFICATION / SELEC / SPCOMPONENT
```

用户手里的 `PKPM（PDMS数据库）.txt` 就是一份这种库的 **DB Listing 文本**（PDMS 自带
`DB Output/DATAL` 导出的重建宏）：1,406,051 B / 70,301 行 / 3 个 CATALOGUE / 12 个 STSECTION /
57 个 STCATEGORY / 533 个 TEXT / 57 个 DTSET / 2,920 个 SPRFILE / 2,920 个 SPCOMPONENT
（`spec/CONTRACT.md` 附录 B.2，本次 R2 验收检查 11 独立复算同数）。

## 2. 目录/规格宏的文法（生成与解析都按这份文法）

### 2.1 命令集（全部来自样本逐字核对，`_recon/db_pdms_catalogue.md`）

* 头尾：`$S-  -- Synonym translation OFF` … `$S+  -- Synonym translation ON`；
  错误处理 `ONERROR GOLABEL <标号>` + `LABEL <标号>` + `handle ANY … RETURN ERROR … endhandle`；
* 建元素：`NEW <TYPE> [名] … END`（`END` 可省，段尾自动收）；
* 引用元素：`OLD <TYPE> <目标>`——**没有 END**，遇到下一条 `NEW/OLD/LABEL/handle` 即结束；
  目标可带**父级限定链**：`OLD SPRFILE /H_Profile of STCATEGORY /USER_H of STSECTION /USER_SECTION of CATALOGUE /PKPM_JWD_USER_<戳>`；
* 引用型属性只在第二遍出现：`PSTR`（PTSSET→SPRFILE）、`GSTR`（GMSSET）、`DTRE`（DTSET）、
  `CATR`（SPRFILE→SPCOMPONENT）、`NARE`（PLINE 条数）；
* `INPUT BEGIN/END/FINISH` 是 DB Listing 输出器的包装，**生成宏不写**（解析器兼容有/无）。

### 2.2 依赖顺序（第一遍 NEW、第二遍 OLD 补引用）

```
第一遍（NEW，父先子后）：
  CATALOGUE → STSECTION → STCATEGORY → TEXT(参数名) → DTSET → DATA
            → PTSSET → PLINE → (GMSSET → SRECTANGLE/SANNULUS/SPROFILE+SPVERT)
            → SPRFILE(GTYP+PARA)
            → SPWLD → SPECIFICATION → SELEC(TANS 'BEAM') → SPCOMPONENT
第二遍（OLD，无 END）：PSTR / GSTR / DTRE / CATR / NARE —— 逐条带父级限定链
```

### 2.3 生成侧的硬性不变量（验收逐条查，契约 §l.3.4）

1. `SPCOMPONENT 名 == /<STCATEGORY 名>-SPEC/<SPRFILE 名>`（样本 2,920/2,920 成立）；
2. `NEW` 与 `END` 严格 1:1；`OLD` 一律不写 `END`；
3. 引用型属性只在第二遍出现；
4. 参数化族的 `TEXT` 条数 == `PURP=PARA` 的 `DATA` 条数；`PURP=DESP` 的 `DATA` 带 `PTYP DIST`；
5. `SELEC` 全部 `TANS 'BEAM'`；
6. 产物**纯 ASCII、CRLF、无 BOM**（写前断言 `text.isascii()`，`engine/dbmacro.py:1354`）。

本次实跑（验收检查 12，宏为带运行戳的生成物）：

```
[jwd2db] 33924 字节；非 ASCII 字节 0；孤立 LF 0；BOM=False
[jwd2db] NEW=166 END=166 OLD=40（两遍结构：NEW/END 1:1、OLD 不写 END）
[jwd2db] 第二遍引用属性：{'PSTR': 16, 'GSTR': 3, 'DTRE': 16, 'CATR': 16, 'NARE': 8}
[jwd2db] 参数化族（DTSET 有 PURP DESP）3 个：['/USER_CIRCLE', '/USER_H', '/USER_RECT']
[jwd2db] SPCOMPONENT 16 条全部挂在 SELEC + TANS 'BEAM' 下：是
[pdt2db] NEW=79 END=79 OLD=16；SPCOMPONENT 6 条全部挂在 SELEC + TANS 'BEAM' 下：是
```

## 3. 四个方向怎么用

### 3.1 `jwd2db` / `pdt2db`：PKPM 截面定义 → 目录+规格宏

```bat
cd /d D:\AI_Work\PKPM数据解析\PKPM-JWD导入导出

:: 从 .jwd 生成（为本工程用到的全部截面建库，含板/墙缺口规格）
python engine\cli.py jwd2db "G:\...\JLCJ2.jwd" --out "jlcj2_db.mac"

:: 从 .pdt 生成（同上，源换成 .pdt；多覆盖墙体规格 WALL-600）
python engine\cli.py pdt2db "G:\...\1_PM.pdt" --out "1pm_db.mac"

:: 清场版（先删本包旧容器再重建，见 §5）
python engine\cli.py jwd2db "G:\...\JLCJ2.jwd" --out "jlcj2_db_clean.mac" --clean --suffix _MYRUN
```

选项（实跑 `--help`，全文存 `test\_acceptance_out\_r2_h_jwd2db.txt`）：

| 选项 | 缺省 | 说明 |
|---|---|---|
| `--out <db.mac>` | 必填 | 输出的目录+规格宏（**纯 ASCII、CRLF、无 BOM**） |
| `--secmap F` / `--extra F` | 输入同目录匹配文件 / `engine\secmap_extra.txt` | 与 `jwd2pdms` 同规则 |
| `--project N` | `pkpmSysInfo.ID=2` | 只是报告/宏头注释里的**标签**（目录宏没有 ZONE 概念） |
| `--suffix S` | `_YYYYMMDD_HHMMSS`（到秒） | 4 个顶层容器名的唯一后缀（§5） |
| `--clean` | 关 | 生成清场版（`OLD … DELETE … MEM`，只清本包容器） |
| `--catalogue-user N` | `/PKPM_JWD_USER` | 参数化族目录名（**必须**带 `/PKPM_JWD_` 前缀） |
| `--catalogue-stss N` | `/PKPM_JWD_STSS` | 型钢库目录名（同上） |

**生成范围**：源文件里实际用到的截面 + 解析它们所需的族模板（TEXT/DTSET/PTSSET/PLINE/GMSSET），
并**补建缺口规格** `/Concrete_Slab-SPEC/T100|T120`、`/Concrete_Wall-SPEC/WALL-<厚度>`
（用户目录宏里没有这批板/墙规格——`db_pkpm_sections.md` §7.3【事实】）。
验收检查 12 实测：jwd2db 覆盖 11 条构件规格 + 2 条板厚规格、缺 0；pdt2db 覆盖 3 条构件规格
+ 板厚 2 条 + 墙 1 条、缺 0。

### 3.2 `db2jwd` / `db2pdt`：目录宏 → PKPM 截面定义

```bat
:: 从用户原件解析出 2,920 条规格 → 写成只含截面定义的 .jwd
python engine\cli.py db2jwd "G:\...\PKPM（PDMS数据库）.txt" --out "db_sections.jwd" --secmap "G:\...\PKPM转PDMS截面匹配文件.txt"

:: 同源 → 写成只含 $DEFFRAMESECTION 的 .pdt（--skeleton sections-only 只写截面段）
python engine\cli.py db2pdt "G:\...\PKPM（PDMS数据库）.txt" --out "db_sections.pdt" --skeleton sections-only
```

* 输入编码自动判定 `utf-8-sig → utf-8 → gbk`（禁止 `errors='replace'`，`engine/dbparse.py:136-144`）；
* 解析器按契约 §l.5 的 12 条规则实现（`$` 续行、`OLD` 无 END、类型缩写归一、
  `PARA` 逐项消化且 word 型参数允许 1–2 token…）；
* 反算覆盖（冻结，不得扩大）：族码 **39**（`/H_INTERNATIONAL`）→ `Kind=26`；族 **77**（`/RECT_*`、`/TUBE_*`）
  → `Kind=303`；`RECT`/`CIRCLE` 模板 → `Kind=1`/`Kind=3`（仅模板，尺寸取 `DPRO` 默认值并标
  `confidence='unknown'`）；**其余族跳过 + 报告**（`not_closable`），不猜；
* 产物是"只含截面定义"的文件：`.jwd` 建**全部 46 张表**但只填三张 `*Sect`；
  `.pdt` 缺省 `full` 骨架（13 段，几何段为空）或 `sections-only`。报告 `warnings` 注明
  「这是截面定义文件，不含几何」。

## 4. 生成的宏怎么在 PDMS 里执行

1. **宏本身就是普通 PDMS 宏**：`$S-` 开头、`$S+` 结尾、纯 ASCII、CRLF。执行方式与导入宏相同：
   * 菜单/窗体：DESIGN → **PKPM-JWD** → 窗体 `宏文件` 填宏全路径 → **运行导入宏**（`$m "<宏>"`）；
   * 命令行：`$m "D:\...\jlcj2_db.mac"`。
2. **执行前先完全退出并重启过 PDMS 的要求不适用**（目录宏不依赖 PML 包，但没有实机验证过任何执行行为）。
3. 宏会创建 4 个**本包自己的顶层容器**（名字带运行戳，见 §5），在其下建目录/规格；
   不会触碰用户的 `/PKPM_STSS`、`/PKPM_USER`、`/PKPMDATA` 等既有目录（§6 安全约定）。
4. 执行后的效果核对（建议，未实机验证）：`!!pkpmjwddbinventory()` —— PDMS 侧 PML 函数
   （`pdms/pkpmjwddbexport.pmlfnc` 提供）按类型计数当前库里的 CATALOGUE/SPWLD/SPRFILE/SPCOMPONENT，
   可与报告 `db.generated` 的计数交叉。

> **未在 PDMS 实机验证**：目录宏从未在 PDMS 12.1 SP4 里执行过。特别是：
> ① `DELETE CATE MEM` / `DELETE SPWL MEM` 的语义只有旁证（官方样例只证明 `DELETE PTSE MEM` /
> `DELETE GMSE MEM`，契约 §12#16）；② 第二遍父级限定链的**链深**（`of STSECTION / of CATALOGUE /
> of SPECIFICATION / of SELEC <n>` 段）是同文法外推，样本只直证一级与两级链（契约 §12#25）；
> ③ `ONERROR GOLABEL` 在 `INPUT BEGIN` 流内的行为。首次上机请先在一个试验库上执行。

## 5. 重跑名冲突怎么办

**背景（事实）**：用户的目录宏里 `OVERRIDE` 0 次、`DELETE` 0 次（`db_pdms_catalogue.md` §6.4）
⇒ PDMS **没有 OVERRIDE**：同一父级下第 2 条同名 `NEW` 必失败，`ONERROR GOLABEL` 会让整个宏中止。

本包的应对（三层，全部已在生成器里实现并实测）：

1. **缺省：唯一名路线**。`uniquify=True`，4 个顶层容器名自动加后缀，**缺省到秒**
   （`_YYYYMMDD_HHMMSS`；`engine/dbmacro.py:120`）——同一天重跑也不会撞名。
   `STSECTION/STCATEGORY/SPRFILE/SPCOMPONENT` **保持源名**：PDMS 名字在属主内唯一，
   新容器内不会与用户库冲突；同时 `SPREF` 的 `/<族>-SPEC/<轮廓>` 路径与用户匹配文件右值完全一致。
   实测（验收检查 12）：`新建容器：['/PKPM_JWD_STSS_20260925_034915', …]（要求 /PKPM_JWD_ 前缀）`、
   `同一父级内重名：0 处`。
2. **显式指定**：`--suffix _MYRUN` 用你自己的后缀；`--catalogue-user/--catalogue-stss` 改容器基名
   （必须 `/PKPM_JWD_` 前缀，否则生成器报错）。
3. **可选清场版 `--clean`**：在宏头（`ONERROR GOLABEL` **之后**，`engine/dbmacro.py:1044-1062`）
   生成 `OLD <本包容器+清场后缀>` + `DELETE <类型缩写> MEM` 四组语句，只针对本包自己的容器。
   注意两点：
   * 清场目标名 = 基名 + **清场后缀**（显式 `--suffix` 原样；缺省 `_YYYYMMDD`），
     **重建容器** = 基名 + 运行戳（`_YYYYMMDD_HHMMSS`）——**绝不复用刚清场的名字**
     （`DELETE … MEM` 只清成员不清容器本身且语义未直证，同名重建必然撞名）；
   * `CATE`/`SPWL` 的 `MEM` 语义**未直证**（契约 §12#16）——清场版是按给定范式生成的**可选**路线，
     **缺省仍是唯一名路线**；用了 `--clean` 请先在试验库验证。

## 6. 只操作本包 CATALOGUE 的安全约定（硬约束）

生成器内置四道闸（契约 §l.1，`engine/dbmacro.py:31/117/154/1040-1062`），报告 `db.safety`
三键机器可见：

1. **白名单容器**：宏只允许创建/修改本包的 4 个容器
   `/PKPM_JWD_USER*`（参数化族目录 + 其 SPWLD）与 `/PKPM_JWD_STSS*`、`/PKPM_JWD_LIB*`
   （型钢库目录 + 其 SPWLD）；
2. **禁用名扫描**：写盘前对全文做字符串扫描，`NEW/OLD/DELETE` 目标命中用户既有容器名
   （`/PKPM_USER`、`/PKPM_STSS`、`/PKPMDATA`、`/PKPM_USER_SECTION`、`/PKPM_LIB`）即抛
   `DbMacroError`（不是警告后继续）。实测（复核脚本 D1/D2）：构造 `/PKPM_LIB` 规格名与
   `/PKPM_STSS` 族名都被拦截；
3. **清场目标校验**：`--clean` 的每个 `OLD/DELETE` 目标必须 ∈ 本包 4 容器（含后缀），
   否则抛错；`clean_targets_owned=True` 进报告；
4. **`USERSTL.LIB` 不作数据源**：它是私有二进制（头 `39 0F 03 00`），16 个 f32 载荷与目录宏
   `PARA` **无一能对上**（`db_pkpm_sections.md` §1.4）；几何/参数一律取目录宏的
   `SPRFILE PARA` + `DTSET` 具名参数。

此外：**用户原件只读**（`PKPM（PDMS数据库）.txt`、`pkpm_section_DBOutput.txt`、匹配文件、
样本 .jwd/.pdt 一律不写）；**宏由用户自行执行，本包不代跑 PDMS**（契约 §n-1/2）。

## 7. 闭环校验怎么做

**判据（计划 §9.4-13）**：`db2jwd`/`db2pdt` 的反算结果再喂回 `jwd2db`/`pdt2db`，
必须回到**同一批规格名**。

```bat
:: 正向：样本 → 目录宏
python engine\cli.py jwd2db "G:\...\JLCJ2.jwd" --out step1.mac
:: 反向：目录宏 → 截面定义
python engine\cli.py db2jwd step1.mac --out step2.jwd --secmap "G:\...\PKPM转PDMS截面匹配文件.txt"
:: 再正向：截面定义 → 目录宏，比对 SPCOMPONENT 集合
python engine\cli.py jwd2db step2.jwd --out step3.mac --secmap "G:\...\PKPM转PDMS截面匹配文件.txt"
```

* `step3` 的 `SPCOMPONENT` 集合 ⊆（✅覆盖族时 ==）`step1` 的集合 ⇒ 闭环成立；
* 报告 `db.closure` 三键**必须存在**：`covered`（可闭环条数）、`not_closable`（族码未解/槽序未知
  而跳过的，逐条带族名与理由）、`differences`（允许的差异，如 `HN300X150` 的 `tw` 目录宏 6.5 vs
  `.jwd` 取整 6 —— 两者映射到同一规格名，记「数值取整差异」不算失败）；
* **不可闭环不是错误**（退出码仍 0），但必须全部落在 `not_closable` 里，不静默。

验收检查 13 实测（我复跑）：

```
db2jwd step1.mac → r2_db2jwd.jwd（退出码 0）；jwd2db r2_db2jwd.jwd → r2_closure_jwd2db.mac（退出码 0）
db.closure：covered=9 not_closable=7 differences=2（三键都在）
闭环结果 ⊆ 原宏规格集：True（原宏 16 条）
db2pdt r2_pdt2db.mac → r2_db2pdt.pdt；pdt2db r2_db2pdt.pdt → r2_closure_pdt2db.mac：3/3 条规格名全部回到
```

## 8. 信息损失申报（双向都有，逐条可查）

`report.db.losses`（生成/解析方向都填）与 `sectionlib.loss_items(direction)`（`engine/sectionlib.py:394`）：

| 方向 | 损失 | 证据 |
|---|---|---|
| PKPM → PDMS | 工程自定义截面（Kind=1/2/3 的具体尺寸）只能落参数化模板（`/USER_RECT-SPEC/…` 等），尺寸变 `DESP` 参数 | 样本 `.pdt` 30 个 `矩*` 均落 `/USER_RECT-SPEC/Rectangle_Profile` |
| PKPM → PDMS | `.pdt` 型钢厚度 `T1..T6` 恒 0，只有 `NAME/NAME1` 可用 | `pdt_format.md` §2.6【事实】 |
| PDMS → PKPM | `PARA` 的力学量（A/g/Ix/Wx/iy…）在 `.jwd/.pdt` **没有字段位** | `$DEFFRAMESECTION` 字段集由 DLL 格式串枚举，无 A/g/Ix |
| PDMS → PKPM | 族码 19 / TRAPEZOID / DOUBLE_C / RECT 的族码值未解；Kind=26 族码≠39 的 6 尺寸槽序未知；Kind=2 未知 ⇒ 这些族**不可反算**（`not_closable`） | 契约 §12#18/§12#19、`conflicts.md` §3/§4 |
| PDMS → PKPM | Kind=303 槽 27/32 是【推断-中】；`PARA` 精度取整（6.5→6） | 契约 §12#20；闭环 `differences` |

**结论**：`.pdt` ↔ `.jwd` 对型钢厚度非无损 ⇒ 两条几何链路各自直连 PDMS，**不做绕道互转**（计划 §9.2）。

## 9. 报告怎么看（`report.json` 的 `db` 块）

生成方向（jwd2db/pdt2db）与解析方向（db2jwd/db2pdt/dbsections）共用 7 个键，缺席写 `null`：

| 键 | 内容（本次实跑实例） |

## 10. 已知限制（务必先读）

1. **未在 PDMS 实机验证**：生成的目录宏、`DELETE … MEM` 语义、限定链深度、ONERROR 行为——全部只有
   静态核对 + 样本文法证据（§4、契约 §12#16/#22/#25）。
2. **反算覆盖面窄是刻意的**：只有族码 39、77 与 RECT/CIRCLE 模板可反算，其余跳过 + 报告（不猜）。
3. **`db2pdt` 的占位块**：不可回算的截面写 `SHAPE=<kind>, B1=H1=0, NAME1=''` 的占位 5 行
   （契约 §j.7.1），引用它的构件照写；对用户目录宏这样反算出来的 `.pdt` 里占位占比很高
   （2,920 条里绝大多数是 `DLEC*/DLU*` 等无编码串的条目）——**这类占位块能否被现有 Add-in
   接受未实机验证**（复核发现，见 `docs/交付报告.md` R2 第 27 条）。要干净的"只含可回算截面"的
   `.pdt`，用 `--skeleton sections-only` 并先看报告的 `not_closable`。
4. **荷载数据库方向也不做**（R2 §9.3）：目录宏本来就只有截面，无荷载内容。
5. 需要自己改映射/补规格时，改 `engine\secmap_extra.txt`（不改用户原件、不改内置表），见
   `docs/截面映射说明.md` §5 与 `docs/转化表说明.md` §6。
