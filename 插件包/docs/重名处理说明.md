# 重名处理说明 —— PDMS 模型树元素的运行期重名唯一化（re / re2 / … / re99）

> 版本：R3（契约 `spec/CONTRACT.md` §(o)、§12#26–#28）
> 落点：`pdms\pkpmjwduniquename.pmlfnc`（10,050 B，GBK 无 BOM + CRLF）+ `engine/macgen.py` 的
> `emit_new` 模板（`engine/macgen.py:582-611`）
> 本文的数字与结论都来自实跑：`python PKPM-JWD导入导出\test\acceptance_r3.py`
> → `{"passed":true,"passedCount":6,"failedCount":0}`（检查 15 + 把关项即本主题）。

---

## 1. 规则：原名 → re → re2 … → re99（共 100 个候选）

```
候选(base) = [ base ] + [ base & 're' ] + [ base & 're%d'  for d in 2..99 ]   ⇒ 共 100 个
```

* 取**第一个未被占用**的候选；后缀**直接拼接、无分隔符**：
  `/STL_COL_1` → `/STL_COL_1re` → `/STL_COL_1re2` → … → `/STL_COL_1re99`；
* 原名本身可用 ⇒ 直接用、**不留任何改名记录**（`pkpmjwduniquename.pmlfnc:137-139`）；
* **只影响名字**：几何、属性、挂接、命名规则（契约 §d）一概不变；
* 覆盖**全部 8 类**被创建元素：骨架 `SITE / ZONE / STRU / FRMW / SBFR` 与元件
  `SCTN / PANE / STWALL`——把关项实测：宏内"唯一化调用数 == 带名 NEW 数"，样本
  `jwd2pdms` 1065/1065、`pdt2pdms` 1443/1443，**字面名 NEW = 0**（无绕过）。
* 与**数据库侧唯一名互不替代**（契约 §o.1 末）：目录/规格宏（`jwd2db/pdt2db`）走生成期后缀
  + 清场（契约 §l），**不走**本机制；本机制只管 **Design 模型树元素**。

## 2. 为什么只能在运行期判断

生成宏的时候**不知道目标 PDMS 库里已有什么名字**——同一份宏要在空库和"已经导过一遍"的库里
都能跑，唯一的办法是**在 PDMS 里逐个探测**。因此逻辑落在 PML 函数
`!!pkpmjwdUniquename(!base is STRING) is STRING`（宏的每个 `NEW` 前调用它），宏里**不写死**最终名：

```pml
!!pkpmjwdType = 'SCTN'                      -- 双 ! 全局：把元素类型传给函数（记录用）
!n = !!pkpmjwdUniquename('/STL_COL_1')      -- 返回可用名（可能带 re 后缀）
if (!n eq '') then
  var !pkpmjwdFatal EXIST $!n               -- 故障注入：!n 为空 ⇒ 该行非法 ⇒ 触发 ONERROR
endif
NEW SCTN $!n                                -- 用返回名创建
```

（`engine/macgen.py:605-610`；`MacOptions.uniquify` 缺省 **True**，False 只是测试用。）

**生成侧不预判库内容**：`macgen._alloc_name`（`engine/macgen.py:334-357`）只消解**宏自身已知**的
信息（同一 SBFR 跨层 `No_` 重复时加 `_EL<层号>` 后缀），这些名字**仍走运行期探测**；
复核确认生成侧没有任何"为绕开运行期探测而拍定最终名"的分支，数据库宏
（`dbmacro.py`）不含 `!!pkpmjwdUniquename`。

**探测的两种已证实写法**（契约 §o.3，出处为本机 PMLLIB 内既有代码）：

| 写法 | 语义 |
|---|---|
| ① `VAR !probe EXIST $!cand` 包在 `handle (2,109)` 里（**本函数用这个**，无副作用） | `!cand` 自带前导 `/`；VAR 正常返回按值判 `'TRUEA'`=已占用 / `'FALSEA'`=可用；落到 `(2,109)`（undefined name）= 可用（**双结局**） |
| ② `NEW <TYPE> <名>` 包在 `handle (41,12)` 里（"建了才知道"的兜底） | 落到 (41,12) ⇒ 重名 |

> **一处经证据修正的实现细节**（复核确认是对的）：早期契约夹具冻结"仅 (2,109)=可用"；
> 实现改为**双结局判定**——因为本机 4 处直证 `VAR EXIST` 对不存在的名字**正常返回 'FALSEA'
> 而不报错**（`assybuildname.pmlfnc:47-50,64-65`、`abaarealib.pmlfrm:304-306`、
> `abauserview.pmlfrm:859-860`、`tgautonum.pmlfnc:32-41`），若按旧夹具实现，全新库里
> 每个空間名都会被误判占用、函数永远 FAIL。偏差在 `pkpmjwduniquename.pmlfnc` 文件头如实声明。
> 另：探测形态统一为 `EXIST $!cand`（**不是** `EXIST /$!cand`——后者会探成 `//名`，
> 全库 0 例的未证实形态，契约 §0.4-12 修订后禁用）。

## 3. 上限与超限行为（re99 也被占用 ⇒ 报错中止整宏）

1. 100 个候选全部占用 ⇒ 函数**不再猜**：向 `!!pkpmjwdRenames` 追加
   `'FAIL|<base>|<base>re99'`，**返回空串**（`pkpmjwduniquename.pmlfnc:145-150` 一带；
   逻辑对照实测：占用 100 个 ⇒ `final=''` + FAIL 记录）；
2. 宏内故障注入行 `var !pkpmjwdFatal EXIST $!n` 在 `!n=''` 时变成无名参数的 `VAR … EXIST`
   ⇒ 非法 ⇒ 触发宏头 `ONERROR GOLABEL /PKPMJWDERR` ⇒ 跳到宏尾
   `LABEL / handle ANY / $S+ / RETURN ERROR / endhandle` ⇒ **整宏中止、上抛给执行者**
   （`engine/macgen.py:486` 宏头、`:756-760` 宏尾；与用户在生产中实际运行的目录宏逐字同构，
   仅 LABEL 名不同）；
3. 中止后**已建的元素保留**（部分建成模型 + 报错，**不是回滚**）——后续元素**不再创建**；
4. **绝不**"跳过该元素继续"也**绝不**"覆盖既有元素"（复核确认 `emit_new` 无任何直写回退路径，
   逻辑对照：re99 占用 ⇒ BM_10 不创建）。

> 语义标注：`(2,109)` 的双结局、空名故障注入都标【待实机确认】（契约 §12#26/27）——
> **未在 PDMS 实机验证**；但两条路线的最坏情形都是经 `ONERROR` 安全中止，不建错名。

## 4. 改名记录在哪看（三处）

| 处 | 内容 | 证据 |
|---|---|---|
| ① **PML 全局数组 `!!pkpmjwdRenames`** | 函数运行期逐条 `append('TYPE\|原名\|实际名')`（三段竖线串；TYPE 经 `!!pkpmjwdType` 双 ! 全局传入；原名可用不留痕） | `pkpmjwduniquename.pmlfnc:96-100,140` |
| ② **PML 窗体 `!!pkpmjwd` 的「改名统计」栏 + 「改名清单」按钮** | 运行导入宏前后调 `!!pkpmjwdRenamesCount()/!!pkpmjwdRenamesFailCount()` 算出"本次因重名改名 N 个"；按钮把 `TYPE\|原名\|实际名` 逐条输出到命令窗 | `pdms\pkpmjwd.pmlfrm:40-44,86-88`（我读原文） |
| ③ **`report.json` 的 `renames` 键**（Python 侧） | 首跑（全部原名可用）= `[]`，**键必须存在**；示例：`[{"type":"SCTN","original":"/STL_COL_1","final":"/STL_COL_1re","reason":"name in use"}, {"type":"FAIL","original":"/BM_9","final":"/BM_9re99","reason":"candidates exhausted"}]` | 契约 §o.7；检查 15 实测 `report.json 含 renames 键，首跑值 = []` |

补充：.NET 窗体路线在宏执行后经 PML 取回 `!!pkpmjwdRenames`，落
`<report>.renames.txt` 旁车文件（`PKPMJWDForm.cs:714-732`，注释如实标注 `Result` 取回形态
**待实机确认**）——与"并入 report.renames"的形态略有差别（复核 low 条目，如实保留）。
**注意**：Python 侧 `report.renames` 首跑恒 `[]`——因为改名发生在 PDMS 运行期，
Python 生成报告时还没进库。

## 5. "生成的文件里仍是原名"（重要）

**改名只发生在 PDMS 侧**。`.mac` / `.dump` / `.jwd` / `.pdt` 等生成文件里写的**全部是原名**
（`NEW SCTN /STL_COL_1` 的形态只出现在 uniquify=False 的测试宏里；交付宏里是
`!n = !!pkpmjwdUniquename('/STL_COL_1')` + `NEW SCTN $!n`）——生成期不知道库内容，
也不应把运行期结果回写进文件。**`report.renames`（或 PML 窗体的改名清单）是"实际用了什么名"的唯一真相。**

回归核对（复核实测，5 组全过）：uniquify=False → True 的宏差异行**全部是名字相关行**
（jwd 侧 7,474 行、pdt 侧 10,120 行，"其他"= 0），非名字行投影逐行一致——
几何/属性/顺序/注释完全不变，变化只有 NEW 行换成唯一化模板 + ONERROR 头尾。
