## 2. 三份来源（外加两个样本做交叉）

行级数据由 `test/build_section_table.py` 从侦察产物
`_recon/dbsect/pkpm_pdms_section_table.csv`（3,176 行 × 38 列，sha256 `fc19f317be9cf9d0…`）
**机械投影**而来；而那份源表由三份用户文件交叉构建（`_recon/dbsect/pkpm_pdms_section_conflicts.md` §1）：

| # | 来源文件 | 规模 | 提供什么 |
|---|---|---|---|
| S1 | `PKPM转PDMS截面匹配文件.txt`（**只读**） | 2,836 数据行 | PKPM 截面名 ↔ PDMS 规格路径（`pkpm_name`、`pdms_spec_path`） |
| S2 | `P-TRANS\PDMSxCA_Addin121.dll`（及 `PDMSxCA_Addin.dll`）内嵌编码表（**只读**） | 2,326 个 PKPM 名，1,131 条紧邻携带编码串 | PKPM 名 ↔ 参数编码串（`shapeval`、`family_code` 的显式证据） |
| S3 | `PKPM（PDMS数据库）.txt`（第 2 份：`P-TRANS\pkpm_section_DBOutput.txt`）（**只读**） | 2,920 SPRFILE / 2,920 SPCOMPONENT / 57 STCATEGORY / 57 DTSET | PDMS 侧规格库（`pdms_catalogue`、族中文名、具名参数、`PARA` 默认值） |

两个**工程样本**只做交叉印证，不提供行：`JLCJ2.jwd` 的 28 条截面行（校准 `jwd_kind`/`shapeval` 列）
与 `1_PM.pdt` 的 32 条 `$DEFFRAMESECTION`（校准 `pdt_kind`）。样本里出现过的行会在
`extra_json.in_jwd_sample / in_matching_file / in_pdms_macro / in_dll_table` 标 `Y`。

> **`USERSTL.LIB` 不是来源**：私有二进制，其 16 个 f32 载荷与目录宏 `PARA` 无一能对上
> （`db_pkpm_sections.md` §1.4，契约 §l.1-4/§12#21）——不作为几何参数源。

## 3. 15 列的含义（列序冻结，不得增删改序）

```
key, pkpm_name, family_code, family_name_cn, kind, shapeval, dims_json, mat,
pdms_spec_path, pdms_catalogue, is_parametric, params_json, confidence, source, extra_json
```

| 列 | 含义 | 读法/例 |
|---|---|---|
| `key` | 唯一键 | `pkpm_name` 非空用它；否则 `pdms_spec_path` |
| `pkpm_name` | PKPM 侧截面名 | 可为空（目录里有、匹配文件没有的条目，381 条：3,176−2,835+重叠） |
| `family_code` | PKPM 族码 | `0` = 未知；型钢族 31/32/33/36…39、参数化族 2/3/15…24/77（conflicts §4.4） |
| `family_name_cn` | 族中文名（原样，含竖线分隔的英文描述） | `用户参数化截面 \| Variable Size` |
| `kind` | `.jwd`/`.pdt` 的 Kind/SHAPE | 只填**样本观测到**的值；`0` = 未知 |
| `shapeval` | PKPM 编码串（DLL 口径） | 如 `39,450,200`；空 = 无编码证据（2335 非空 / 3176） |
| `dims_json` | 尺寸键值 | 键空间同契约 §a.4（`H/B/tf/tw/d/B/H`…）；由位置规则 + 具名参数两路解出，**冲突不调和**，记 `extra.param_check='mismatch'` |
| `mat` | 材料 | **常量 5（钢）**：内置表条目全部来自 PDMS 钢结构目录；`.jwd/.pdt` 给的真实 `Mat` 优先（调用方覆盖） |
| `pdms_spec_path` | PDMS 规格全名（SPCOMPONENT） | `/H_INTERNATIONAL-SPEC/HN450X200`；57 个规格属主 |
| `pdms_catalogue` | 所属 CATALOGUE | `/PKPM_STSS`（型钢）或 `/PKPM_USER`（参数化） |
| `is_parametric` | 是否参数化族（DESP 驱动） | **仅 15 条 true**（`/USER_*` 模板行） |
| `params_json` | 具名参数表 | `[{"name":"B1","desp_index":1,"default":"250"}, …]`；`desp_index>0` 仅当 `is_parametric=true` |
| `confidence` | 置信度 | 见 §3.1 |
| `source` | 溯源组合串 | 见 §3.2 |
| `extra_json` | 其余溯源（24 列原样 + 派生） | `in_pdms_macro/in_matching_file/in_dll_table/in_jwd_sample/name_variants/dll_siblings/stcategory_params…`；**审计所需，不得为体积删列**（契约 §k.2） |

### 3.1 `confidence` 怎么读

词表冻结为 `high / medium / low / unknown`（未知一律 `unknown` 且 `extra.reason` 必填）。
本表实测分布（meta.json `stats.confidence`，检查 14 复核）：

| 值 | 条数 | 含义（构建口径） |
|---|---:|---|
| `high` | 1,146 | 三源（目录宏 + 匹配文件 + DLL 显式编码对）互相印证 |
| `medium` | 1,433 | 两源印证（如宏 + 匹配文件，DLL 编码被 .NET 字符串堆去重拿不到） |
| `low` | 597 | 单源可查（通常只有匹配文件名对得上，参数从属主具名参数反推） |
| `unknown` | 0 | —（未知族码的条目落 `family_code=0` 并在 extra 里带 reason） |

### 3.2 `source` 怎么读

组合串，`+` 连接该行的证据来源，例如：

* `macro+match+dll_explicit` —— 目录宏有该规格、匹配文件有该名、DLL 里还有显式编码对；
* `macro+match+dll_explicit+jwd` —— 再加"JLCJ2.jwd 样本里也出现"（如 `HN450X200`）；
* 只有 `match` 的行 = 匹配文件独有（若其右值又不在目录宏里，就是 §4 的失效行）。

`extra_json` 是它的展开：每个 `+` 对应一个 `in_*` 布尔列 + `name_variants`
（同一截面在各源里的拼写对照，如 `sprfile=/HN450X200 ; match=HN450X200 ; dll=HN450X200 ; jwd=HN450X200`）。

## 4. 已知冲突（照实申报，**表与原件都不自动修**）

以下数字全部来自本次实跑（`acceptance_r2.py` 检查 11/14，报告 `db.cross_check`）与
`_recon/dbsect/pkpm_pdms_section_conflicts.md`：

### 4.1 匹配文件右值失效：260 条（归一后 258）

匹配文件 2,836 条数据行里，右值在目录宏里**精确命中 2,579 条**；失效 260 条 =
**256 条 Double-L 三族缩写不一致** + **4 条缺前导 `/`**（L2979–2982）。归一化（补 `/`）后 3 条命中，
剩 1 条 `组卷L75X20X2.5-421`（规格名多了 `-421` 后缀）仍失效 ⇒ 归一口径 258 条。

| 失效属主 | 条数 | 匹配文件写法 | 宏里实际是 |
|---|---:|---|---|
| `/DOUBLE_L_EQUAL_CROSS-SPEC/` | 114 | `DLE<B>x<t>` | `DLEC<B>x<t>`（多一个 C） |
| `/DOUBLE_L_UNEQUAL_LONG-SPEC/` | 71 | `LU<b>x<t>x<s>` | `DLU<b>x<t>x<s>` |
| `/DOUBLE_L_UNEQUAL_SHORT-SPEC/` | 71 | `LU<b>x<t>x<s>` | `DLUS<b>x<t>x<s>` |
| `/DOUBLE_THIN_L_COIL_EQUAL-SPEC/` | 1 | `DLTC75X20X2.5-421`（且缺前导 `/`） | `DLTC75X20X2.5` |

（与 v1 `SectionMap.validate()` 的"257 条坏映射"是同一批：256 缩写 + 1 后缀，见
`docs/截面映射说明.md` §4——那边逐条列了 257 行纠正建议。）

### 4.2 大小写/写法差异：759 对

同一截面在匹配文件与 DLL 名集里拼写不同（典型：角钢 `L20X4` vs `L20x4`——大小写；
另有 `[-`、`C[` 等符号写法差异）。样例（检查 11 实跑）：`[(40, 'L20X4', 'L20x4'), (41, 'L25X3', 'L25x3'), (42, 'L25X4', 'L25x4')]`。
工具比较时**空白归一化但不改大小写**（契约 §e.2/§k.1），所以这 759 对在**严格匹配**下查不到——
需要时在 `engine\secmap_extra.txt` 里把你要用的那条拼写补上（§6）。

### 4.3 族码 19（`UNEQUEAL_T`）——推断，未互证

DLL 尾部相邻族名块里 `UNEQUEAL_T` 紧跟 `TEE`(18) 之后但没配到数字；15–24 连续块唯一缺号是 19
⇒ **推断** 族码 19 = UNEQUEAL_T（`conflicts.md` §4.2）。**表里该族 `family_code` 置 0**，
`db2jwd/db2pdt` 遇到即跳过 + 报告。

### 4.4 TRAPEZOID / DOUBLE_C / RECT —— 族码未知

三族的编码串被 .NET `#US` 字符串堆去重，DLL 里看不到值，匹配文件里也没有能反查的实例
（`conflicts.md` §4.3）⇒ **不解**。其中 `RECT` 另按契约 §k.3 处理为 `Kind=1` 模板
（尺寸取 DTSET `DPRO` 默认值 500/500，`confidence='unknown'`）——只是模板，不是具体尺寸。

### 4.5 Kind=2（焊接 H）的槽序未知

样本只有 2 条且对称（`2,10,500,250,16,250,16,5,4080,`），B/T 交错序无法判定
（`conflicts.md` §3；契约 §12#4/§12#18）⇒ `encode_shapeval` 对 Kind=2 **抛 `unencodable`**，
生成侧写占位 + 报告，不猜。

### 4.6 族码 32（槽钢）等 6 尺寸槽序未知

Kind=26 只有族码 **39**（HN/HW/HM）能靠名反推 H/B 并双向闭环（`26,39,1,450,0,200,14,9,0,5,4484,`
与样本逐字一致——检查 14/闭环实测）；族码 31/32/33/36/37/38/40/66/71/72/73 的 6 个尺寸槽顺序未知
（`[18a` 即族 32 轻型槽钢，其 `9,5` 与 GB707 普通槽钢对不上是因为比错了表）⇒
`db2jwd` **只支持族码 39**，其余跳过 + 报告（契约 §12#19）。

### 4.7 其他

* 宏有、匹配文件没有的 SPRFILE：**344** 条（SPCOMPONENT 口径）/ 341（SPRFILE 叶子名口径，检查 11 两种口径都对上）；
* `.pdt` 样本 32 个截面名只有 2 个（`HN400X200/HW200X200`）在匹配文件里 ⇒ 导出方向这类
  "矩*/圆形*"自定义截面只能落参数化模板（`conflicts.md` §2.7）。

## 6. 怎么自己修

**原则（契约 §n-5）**：不改用户原件；**不改内置表本身**（它是冻结数据文件）；
一切纠正写进**补充文件** `engine\secmap_extra.txt`。

| 场景 | 做法 |
|---|---|
| 某截面名（或大小写变体）解析不到规格 | 在 `engine\secmap_extra.txt` 加一行 `<确切拼写>, <你的规格路径>`（GBK/CRLF、`//` 注释、语法与原件相同） |
| Double-L 三族失效右值 | 同上，例如 `+2L20X3, /DOUBLE_L_EQUAL_CROSS-SPEC/DLEC20X3`（纠正建议逐条见 `docs/截面映射说明.md` §4.3） |
| 板/墙厚度规格 | `T120, /你的板规格-SPEC/T120`（现有 3 条是**占位**，请按自己的库替换） |
| 想让某个 `Kind#参数` 点名映射 | 兜底键：`3#20, /TUBE_TUBE-SPEC/D20X2.5` |

**改完怎么验证**：

```bat
python test\pdt_secmap_selfcheck.py          :: 匹配文件解析 + 257 条坏映射基线（仍应 257，原件没变）
python PKPM-JWD导入导出\test\acceptance.py   :: v1 7 项
python PKPM-JWD导入导出\test\acceptance_r2.py :: R2 13 项（含转化表校验和核对）
```

**改表本身（仅当你确实要）**：改 `_recon/dbsect/` 下的源数据（那不是用户原件），
然后 `python test\build_section_table.py` 重新生成——生成器幂等，合法改动会体现在
meta.json 的 sha256 变化里；改完 R2 检查 14 的校验和断言需要同步更新（那是它自己的期望值文件）。
**不要**手编 `engine/section_table.csv`（下次重生成会覆盖你的手改，且验收对不上）。
