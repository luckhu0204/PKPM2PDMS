## 3. 主用法：PDMS 内菜单 + 窗体

### 3.1 原生窗体（.NET 插件，R3 主界面）

DESIGN 模块 → 菜单栏 **「PKPM JWD」** → **「PKPM JWD 导入导出」** → 窗体
（标题「PKPM JWD 导入导出」，非模态）。控件自上而下：

| 区 | 控件 | 填什么 |
|---|---|---|
| 操作 | 下拉 `cmbOp` | 10 个操作：`jwd2pdms / pdt2pdms / pdms2jwd / pdms2pdt / jwd2db / pdt2db / db2jwd / db2pdt / jwd2pdt / pdt2jwd`（缺省 `jwd2pdms`） |
| 输入 | 源文件 / 截面匹配 / 补充映射 | 源类型按扩展名判定；匹配文件缺省取源文件同目录的 `PKPM转PDMS截面匹配文件.txt`；补充映射缺省勾选 = 自动加载 `engine\secmap_extra.txt` |
| 建模参数 | 基点 ENU / 转角 / 单位 | 仅 `*2pdms` 方向启用（语义见 §4.2） |
| 构件类别 | 8 个勾选框 | 按契约冻结保留；**暂未传给引擎**（CLI 暂无对应参数，复核已注明） |
| 输出 | 输出文件 | 缺省 `%TEMP%\PKPMJWD\<源基名>.<ext>` |
| 执行 | 「执行」+ 进度条 | .NET 写 request JSON → 进程调引擎（超时上限 30 分钟）→ 建模方向成功后自动 `$M <生成的宏>`（宏内含重名唯一化）→ 取回改名记录 |
| 结果 | 摘要区 + 「打开报告」 | 引擎 stdout 摘要（含未解析截面清单）+ 用系统默认程序打开 report.json |

### 3.2 PML 窗体（legacy，但命令行兜底入口最常用）

命令行 `$m "%PMLLIB%/pkpmjwd/pkpmjwdrun.mac"`（装完 2.2 后可用；该宏会**先预载重名唯一化函数**
再开窗体，`pdms\pkpmjwdrun.mac:22-26`）。窗体三行功能：

| 行 | 功能 | 说明 |
|---|---|---|
| ① | 运行导入宏 + **改名统计/改名清单** | 填 Python 生成的 `.mac` 全路径 → `$m` 执行；「改名统计」显示本次因重名改名 N 个（重名自动加 re/re2/…，详见 `docs/重名处理说明.md`） |
| ② | 导出当前模型到 PDMSDUMP 文本 | `!!pkpmjwdexport(scope, out)`，缺省写 `%PDMSUSER%\pkpmjwd_dump.txt` |
| ③ | 导出目录/规格（DB Listing） | `!!pkpmjwddbexport(out)`，供 Python 侧 `dbparse` 解析 |

### 3.3 宏会建什么（建模方向）

```
SITE  /PKPM_JWD
└ ZONE  /<工程名>                 ← --project（缺省取 pkpmSysInfo.ID=2，样本 "JLCJ2"）
  └ STRU  /MAINFRAME
    ├ FRMW  /STL_FRAME/EL<n>      n = 层号（.jwd 5 层；.pdt 按 $NODECOOR 不同 Z 建平面）
    │   ├ SBFR /COLUMN → SCTN /STL_COL_<No_>      （重名自动 re/re2/…，§6）
    │   ├ SBFR /BEAM   → SCTN /BM_<No_>
    │   ├ SBFR /HBRACE → SCTN /HB_<No_>（水平）/ SBFR /VBRACE → SCTN /VB_<No_>（竖向）
    ├ FRMW  /FLOOR&WALL
    │   ├ SBFR /SLAB   → PANE  /SLAB_<No_>
    │   └ SBFR /WALL   → STWALL /W_<No_>
    └ FRMW  /GRID      只建该 FRMW（契约 §d.1）
```

`SCTN`/`PANE` 用 `SPREF`（+可选 `DESP`）、墙 `STWALL` 用 `SPRE`、坐标 `POSS/POSE E.. N.. U..`。
语法逐条带本机 `PMLLIB` 出处（契约 §d.3）。**未实机验证**：宏从未在 PDMS 里执行；
`FRMW` 名含 `/`、墙用 `SPRE` 为契约 §12#1/#2 冻结裁定，待实机确认。

## 4. 备用/批处理：外置命令行（12 个子命令）

> R3 起 CLI 降为**备用与批处理途径**——功能与窗体完全同源（.NET 窗体内部就是调它），
> 但没有 PDMS 内的界面；适合脚本化与无 PDMS 会话的纯文件转换。

### 4.1 子命令矩阵（实跑 `python engine\cli.py --help`；各子命令 `--help` 存 `test\_acceptance_out\_r2_h_*.txt`）

| # | 子命令 | 作用 | 必需参数 |
|---|---|---|---|
| 1 | `jwd2pdms` | `.jwd` → PDMS 建模宏 | `<jwd> --out <macro.mac>` |
| 2 | `pdt2pdms` | `.pdt` → PDMS 建模宏 | `<pdt> --out <macro.mac>` |
| 3 | `pdms2jwd` | PDMSDUMP 文本 → `.jwd` | `<dump> --out <out.jwd>` |
| 4 | `pdms2pdt` | PDMSDUMP 文本 → `.pdt` | `<dump> --out <out.pdt>` |
| 5 | `jwd2db` | `.jwd` 截面定义 → 目录+规格宏 | `<jwd> --out <db.mac>` |
| 6 | `pdt2db` | `.pdt` 截面定义 → 目录+规格宏 | `<pdt> --out <db.mac>` |
| 7 | `db2jwd` | 目录宏 → `.jwd` 截面定义（含闭环） | `<db.macro> --out <out.jwd>` |
| 8 | `db2pdt` | 目录宏 → `.pdt` 截面定义（含闭环） | `<db.macro> --out <out.pdt>` |
| 9 | `jwd2pdt` | `.jwd` → `.pdt`（走规范模型） | `<jwd> --out <out.pdt>` |
| 10 | `pdt2jwd` | `.pdt` → `.jwd`（走规范模型） | `<pdt> --out <out.jwd>` |
| 11 | `dbsections` | 列出/导出截面字典与转化表 | `<db.macro>\|--from-builtin --out <F.csv\|F.json>` |
| — | `pdt2model` | `.pdt` → 规范模型 JSON（v1 原有） | `<pdt> --out <model.json>` |

R3 新增（对用户不暴露）：全局选项 `--request <JSON 文件>`——.NET 窗体的引擎调用协议
（`{"tool":…,"args":{…}}`，键名 = CLI 长选项去 `--`；`engine/cli.py:2227-2358`）。

### 4.2 通用参数

| 参数 | 缺省 | 含义 |
|---|---|---|
| `--secmap F` | 输入同目录的 `PKPM转PDMS截面匹配文件.txt` | 截面匹配文件；找不到退出码 2 |
| `--extra F` | 自动加载 `engine\secmap_extra.txt` | 补充映射；**给定时只加载给定文件** |
| `--report R.json` | `<--out 同目录>\<--out 基名>.report.json` | 报告文件 |
| `--project N` | `pkpmSysInfo.ID=2`（几何命令）/ 仅标签（数据库命令） | PDMS ZONE 名 |
| `--base E N U` / `--angle D` / `--unit {mm,cm,m}` | `0 0 0` / `0` / `mm` | 基点/转角/宏内数值单位。公式：`E=base_e+(x·cosθ−y·sinθ)`、`N=base_n+(x·sinθ+y·cosθ)`、`U=base_u+z`；`--unit` 只缩放宏内数值，**不在宏里发单位语句** ⇒ 必须保证 PDMS 会话单位 = `--unit`（否则坐标/板厚/DESP 静默差 10/1000 倍） |
| `--dump-unit {mm,cm,m}` | `mm` | dump 无 `UNITS` 行时生效 |
| `--skeleton {full,sections-only}` | `full` | `.pdt` 写出骨架 |
| `--suffix S` / `--clean` / `--catalogue-user/--catalogue-stss` | 见 `docs/数据库转化说明.md` §5 | 仅 `jwd2db/pdt2db` |

### 4.3 退出码（全部子命令统一）

`0` 成功（允许 unresolved/不可闭环，但必须打印清单并写报告）；`1` 未捕获异常；
`2` 参数/输入文件错误；`3` `Model.validate()` 有 `E-` 项（不写产物）。

### 4.4 两个方向的完整步骤（命令行口径）

**导入**：`jwd2pdms/pdt2pdms` 出宏 → 把宏路径填进 PDMS 窗体「运行导入宏」（或 `$m "<宏>"`）。
实跑（检查 1/10/把关）：`jwd2pdms` 宏 240,659 B、梁 598/柱 200/支撑 13/板 222 全对齐、
唯一化调用 1065/1065；`pdt2pdms` 宏 313,632 B、唯一化调用 1443/1443。

**导出**：PDMS 窗体 ② 出 `#PKPM-JWD-PDMSDUMP 1.0` 文本（GBK）→ `pdms2jwd/pdms2pdt` 写库/写文件。
实跑（检查 6）：自造 dump → `pdms2jwd` 退出码 0、45 对外键不可解析 0。

## 6. 重名怎么办（R3 新增；详见 `docs/重名处理说明.md`）

宏里每个被创建元素（8 类）在 `NEW` 前都调 PML 函数 `!!pkpmjwdUniquename`：库里已有同名 ⇒
**自动加后缀 `re`、再冲突 `re2`…`re99`（共 100 个候选）**；全占用 ⇒ 留 `FAIL` 记录并**中止整宏**
（不跳过、不覆盖）。改名记录三处可查：PML 全局 `!!pkpmjwdRenames`、PML 窗体「改名统计/改名清单」、
`report.json` 的 `renames` 键。**生成的文件里仍是原名**（改名只发生在 PDMS 运行期）。
候选耗尽与探测语义标【待实机确认】（契约 §12#26/27）。

## 7. 报告 `report.json` 怎么看

字段：`counts / sections.detail / sections.unresolved / geometry_anomalies / skipped / warnings /
assumptions / errors / stats`，数据库方向追加 **`db`** 块（`generated/parsed/cross_check/closure/
losses/safety`），R3 起 **`renames`** 键必在（首跑 `[]`）。
看报告四要点：① `errors` 空；② `sections.unresolved`+`inferred` 逐条过；③ 数据库方向看
`db.closure.not_closable` 与 `db.losses`；④ `db.safety` 三键在（生成方向 `forbidden_names_scanned=true`、
`ascii_only=true`）。
