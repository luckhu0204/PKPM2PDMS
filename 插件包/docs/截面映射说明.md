# 截面映射说明 —— `PKPM转PDMS截面匹配文件.txt` 与 `secmap_extra.txt`

> 本文说明三件事：① 用户原件的**语法与容错规则**；② **257 条已知坏映射**的完整清单与纠正建议；
> ③ 交付包自带的补充文件 `engine\secmap_extra.txt` 怎么用、怎么自己加条目。
> 文中所有数字都来自本次实跑，命令见 §6。

---

## 1. 两个文件的角色

| 文件 | 归谁 | 本包怎么对待 |
|---|---|---|
| `PKPM转PDMS截面匹配文件.txt` | **用户原件**（在插件目录下） | **只读**。绝不改写、不重排、不补全 |
| `engine\secmap_extra.txt` | **本包新增** | 补充缺口的唯一合法位置；格式与原件**完全相同** |

它们在工具里的角色是同一个：把"PKPM 侧的截面标识"翻译成"PDMS 等级库里的规格路径"。
翻译结果决定宏里 `SPREF` / `SPRE` 写什么（板/墙由 `Section.for_panel` 合成 `T<厚度>` 键后再查）。

**加载顺序**：原件 → `secmap_extra.txt`（同名左值以**补充文件**为准，并记 `warnings`）。
`--extra F` 指定其它补充文件时，**默认补充文件不再加载**（避免隐性叠加）。

## 2. 文件语法（原件实测）

| 项目 | 事实 | 本次证据 |
|---|---|---|
| 编码/换行 | **GBK、CRLF、无 BOM** | 读出 3,023 个 `split("\r\n")` 元素、无 BOM |
| 物理行 | **3,023 行**（含末尾 CRLF 后的空元素） | `test\check_deliverables.py` |
| 数据行 | **2,836 条** | `SectionMap.load()` → `entries(原件) = 2836` |
| 注释 | **只有 `//` 一种**：`///`、`// DESC '…'`、`//+`、`//short` 都算注释；另有**整行只有 `/`** 的分隔线 | 统计：`//` 注释 78 行、空行 109 行 |
| 左值唯一 | 2,836 条数据行**左值 0 重复** | `check_deliverables.py` 实测 |
| 规格前缀 | 共 **53 个**（只作信息统计，不参与判断逻辑） | `report.json` 的 `stats.secmap.spec_prefixes` |

### 2.1 数据行格式

```
<PKPM 截面名>,<空白><PDMS 规格路径>
```

* 逗号两侧空白随意；**右值可能缺前导 `/`**（原件里正好 4 条：第 **2979–2982** 行，
  如 `组卷L40X15X2.0, DOUBLE_THIN_L_COIL_EQUAL-SPEC/DLTC40X15X2.0`）⇒ 解析时**自动补 `/`**；
* **大小写严格区分**（原件同时存在 `L25X3` 与 `3-L25x16x3`）⇒ 比较前**只**做空白归一化与前导 `/` 补齐，
  **不改大小写**；
* 无法解析（没有逗号等）的行 ⇒ 记 `warnings`，**不静默忽略**（本次原件 `unparsable = 0`）。

### 2.2 实际样例（原件里查得到）

```
HN450X200 ,/H_INTERNATIONAL-SPEC/HN450X200        // 型钢库截面（Name 直接命中）
RECT, /USER_RECT-SPEC/Rectangle_Profile           // 参数化族（混凝土矩形）
H   , /USER_H-SPEC/H_Profile                      // 参数化族（焊接 H）
CIRCLE, /USER_CIRCLE-SPEC/Circle_Profile          // 参数化族（圆形，Kind=3 推断用）
```

## 3. 一个截面是怎么被"翻译"的（四级优先级）

严格按序、命中即止（`engine\secmap.py` 的 `resolve()`）：

```
1) Section.Name 非空 且 在匹配文件（原件或补充文件）中命中            → status='resolved'   source='name'
2) 否则按 ShapeVal 解码出候选键，逐个查匹配文件                        → status='resolved'   source='shapeval'
3) 否则走用户参数化族（RECT / H / CIRCLE → /USER_*-SPEC/… + DESP 参数） → status='parametric' source='family'
3b) 否则按补充文件的 @FAMILY 指令走"推断族"                            → status='inferred'   source='family'
4) 全都失败                                                          → status='unresolved' source='none'
```

**候选键（按序尝试，命中即止）**：

| 序 | 候选键 | 适用 | 例 |
|---|---|---|---|
| 0 | `Section.name` 原样 | 全部（非空时） | `HN450X200` |
| 1 | `<子类型>-<name>` | Kind=26 且有子类型 | `[18a` → `2-[18a` → `/C_LIGHT-SPEC/CL18a` |
| 2 | `<族码>-<打包规格串>` | Kind=303 | `6-B250*10.00` → `/RECT_SQUARE6728_2002-SPEC/B250*10.00` |
| 3 | `T<厚度>`（`%g`） | 板/墙（合成截面） | `T120`、`T100`、`T600` |
| 4 | `矩<B>X<H>` | Kind=1 | `矩750X750`（原件**没有**此类条目，主要用于补充文件） |
| 5 | `<Kind>#<ShapeVal 参数体>` | 全部（兜底键） | `3#20`、`26#39,1,450,0,200,14,9,0` |

第 5 条是**兜底**：只要能拿到 `ShapeVal` 原文，就能为**任何**截面在补充文件里点名一条映射。

**四类状态的含义**：`resolved` = 原件/补充文件里写明的映射；`parametric` = 走 `/USER_*-SPEC/` + `DESP`；
`inferred` = **有证据的判定**（当前只有 Kind=3 → 圆形，见 §5.3），报告里必须带 `evidence`；
`unresolved` = 没证据、不猜，宏里省略规格行并写 `-- UNRESOLVED SECTION` 注释（**构件几何照建**）。

## 4. 257 条已知坏映射（原件问题，不阻断流程）

### 4.1 怎么来的

用**随包的 PDMS 目录宏** `PKPM（PDMS数据库）.txt`（UTF-8 带 BOM、70,301 行、
`NEW SPCOMPONENT` 2,920 条）当"PDMS 侧实际存在什么规格"的真值，
逐条检查原件右值是否真的存在于该目录里：

* 右值不在 `NEW SPCOMPONENT` 集合里 → `specmap L<行号> <左值> -> <右值> : SPCOMPONENT 不存在；建议改为 …`
* 右值的 `-SPEC` 属主不存在 → `… : 属主 <X>-SPEC 不存在`

**本次实跑**（`SectionMap.validate()`，只读）：

```
entries(原件) = 2836  extra(补充) = 3   warnings = 0
坏映射条数 = 257
按类型: SPCOMPONENT 不存在 = 257   属主不存在 = 0
带纠正建议的 = 257
```

### 4.2 分族统计与纠正规律

| 属主（`-SPEC`） | 条数 | 左值形态 | 右值少了什么 | 纠正建议（全部 257 条都给出唯一候选） |
|---|---:|---|---|---|
| `/DOUBLE_L_EQUAL_CROSS-SPEC` | 114 | `+2L<B>X<T>` | 规格名 `DLE…` **缺一个 `C`** | `DLEC…`（同属主下编辑距离最小的现存截面） |
| `/DOUBLE_L_UNEQUAL_LONG-SPEC` | 71 | `长2L<b>X<t>X<s>` | 规格名 `LU…` **缺 `D`** | `DLU…` |
| `/DOUBLE_L_UNEQUAL_SHORT-SPEC` | 71 | `短2L<b>X<t>X<s>` | 规格名 `LU…` **缺 `DUS`** | `DLUS…` |
| `/DOUBLE_L_THIN_L_COIL_EQUAL-SPEC` | 1 | `组卷L75X20X2.5` | 规格名**多了 `-421`** | `DLTC75X20X2.5` |

四点结论：

1. 这 257 条**全部是"右值不存在"**，没有一条是属主缺失 ⇒ 属主名（`-SPEC`）本身没问题；
2. 每条都能在**同一属主**下找到唯一的"编辑距离最小的现存截面" ⇒ 建议值可靠，且**改动面只在一行**；
3. 涉及行号集中在 **L2565–L2982**（角钢/槽钢族），与样本 JLCJ2 用到的截面**无交集**
   （样本用到的截面走 `name`/`shapeval` 命中，见 §5）；
4. 本工具**不会自动改原件**：`validate()` 只把清单写进报告/返回值，改与不改由用户决定。

## 5. `engine\secmap_extra.txt`（本包新增的补充文件）

### 5.1 为什么需要它

1. **原件里没有板/墙条目**：`.pdt` 的墙板截面名就是 `T<厚度mm>`（样本 `T600/T120/T100`），
   而契约规定板/墙只能用 `T<厚度>` 键去查规格 ⇒ 原件查不到，必须在补充文件里显式给出；
2. **本包不允许改原件** ⇒ 一切缺口都写在这里；
3. **推断族必须能"一行关掉"** ⇒ `@FAMILY` 指令行也在这里。

### 5.2 当前内容（`engine\secmap_extra.txt`，GBK 无 BOM + CRLF）

数据行只有 3 条：

```
T120, /Concrete_Slab-SPEC/T120
T100, /Concrete_Slab-SPEC/T100
T600, /Concrete_Wall-SPEC/WALL-600
```

外加 1 条指令行：

```
@FAMILY 3 = CIRCLE
```

文件本身共 58 行（3 数据行 + 52 注释行 + 2 空行 + 1 指令行），其余全是解释性注释。

> **重要**：这 3 条右值是**占位**——随包的 `PKPM（PDMS数据库）.txt` 是**钢材**目录宏
> （57 个 SPCOMPONENT 属主全是钢截面），所以这 3 条必然被 `SectionMap.extra_issues()` 报
> "不在目录宏里 / 属主不存在"（本次实跑 6 条消息）。**那是预期，不是错误**；
> 用之前请把它们改成你**自己的 PDMS 等级库里真实存在**的板/墙规格。

### 5.3 指令行 `@FAMILY <kind> = <族键|none>`

* **唯一允许**的非 `左值,右值` 行形式（其余非注释行仍须含逗号）；
* 语义：`Kind=<kind>` 的单尺寸截面按**推断族** `<族键>` 解析；`= none` 表示**强制回 `unresolved`**；
* 后加载者覆盖（与左值映射同规则）；未知族键 ⇒ 记 `warnings` 且**不启用**（不许猜）；
* 已知族键：`CIRCLE` → `/USER_CIRCLE-SPEC/Circle_Profile`，`desp_params=[d]`。

**当前生效的是 `@FAMILY 3 = CIRCLE`**（样本 12 根屋面水平支撑，`pkpmBraceSect ID=32335`，
`ShapeVal='3,20,5,32335,'`）：

* 判定证据（4 条，逐条可查）：
  ① `1_PM.pdt:2387-2388` `ID=1009, NAME=圆形4800, SHAPE=3` + `KIND=3, B1=4800`（B1 即直径）；
  ② 同一 JLCJ2 模型把"薄壁方钢管: B20"归 `Kind=303` ⇒ 排除方管；
  ③ `PKPM（PDMS数据库）.txt:2502-2513` 的 `/USER_CIRCLE` DTSET 只有**一个**参数
  `DKEY D / PTYP DIST / PPRO ( ATTRIB DESP[1] ) / NUMB 1` ⇒ `DESP` 只发一个数 = 直径；
  ④ 原件第 27 行 `CIRCLE, /USER_CIRCLE-SPEC/Circle_Profile`。
* 残余风险：不能 100% 排除 `d=20` 是别的单尺寸族；影响面仅这 12 根支撑；
* **改法**：把该行改成 `@FAMILY 3 = none` 即回到 `unresolved`（宏里这 12 根不再有 `SPREF/DESP`，
  只留 `-- UNRESOLVED SECTION` 标记）。**宁可少写规格，也不写没证据的规格。**

### 5.4 怎么自己加条目

**（1）补一个板/墙厚度**（最常见）：

```
T150, /你的板规格库-SPEC/T150
```

**（2）用兜底键点名一个具体截面**（`<Kind>#<ShapeVal 参数体>`）：

```
3#20, /TUBE_TUBE-SPEC/D20X2.5            // Kind=3、d=20
26#39,1,450,0,200,14,9,0, /H_INTERNATIONAL-SPEC/HN450X200
```

**（3）用截面原名直接命中**（第 1 级）：

```
HN450X200, /H_INTERNATIONAL-SPEC/HN450X200
```

### 5.5 加条目时的三个注意

1. **格式必须与原件一致**：`<左值>, <右值>`，注释用 `//`；文件存成 **GBK、CRLF、无 BOM**
   （否则 PDMS 侧读 `.mac` 时可能报错，也因为原件的解析器按 GBK 读）。
2. **右值一定要在你自己的 PDMS 等级库里真实存在**：右值会原样写进宏的 `SPREF`/`SPRE`，
   写错了 PDMS 会报 spec not found（本工具**不做**这个校验——目录宏只是钢材目录宏，
   校验它会给出一堆假警报；真要校验，用 `SectionMap.validate(目录宏路径)` 并把它当"参考"）。
3. **别写"截面原名"来抢第 1 级**：例如把 `薄壁方钢管: B25` 写进来，会让该截面的
   `Resolution.source` 从 `shapeval` 变成 `name`（报告口径变化，契约 §h 的示例正是 `source='shapeval'`）。
   本包**刻意不写**这些条目——它们已经由 `ShapeVal` 打包串命中。
